**Sprint item:** Stabilization Tier 1, item 2
**Status:** Phase 1 — foundation shipped May 11, 2026. Phase 2 deferred.
**Owner:** Hursh + Claude

## The audit (May 11, 2026)

The codebase has **473 `as unknown as` casts** across `apps/web/`. Every
cast is a place where DB shape and code expectation can drift
invisibly. Tonight's `planning_tasks.budget_line_id` 500 was exactly
this pattern.

**Tables in `packages/db/src/types.gen.ts`:** 33
**Tables called via `supabase.from(...)` in code:** 50+
**Gap:** ~20 tables exist in prod but aren't typed → every access uses a cast

### Top 10 tables ranked by cast-pattern frequency

| Rank | Table | Calls in code | In types.gen.ts? |
|---|---|---|---|
| 1 | `users` | 157 | ✅ (mostly typed) |
| 2 | `workspaces` | 84 | ✅ (but missing newer cols: skin) |
| 3 | `vendors` | 47 | ❌ **not in types** |
| 4 | `guests` | 36 | ✅ |
| 5 | `venues` | 26 | ✅ |
| 6 | `organizations` | 25 | ✅ |
| 7 | `planning_tasks` | 21 | ✅ (missing newer cols: budget_line_id, estimated_cost) |
| 8 | `leads` | 21 | ❌ **not in types** |
| 9 | `testimonials` | 18 | ❌ **not in types** |
| 10 | `proposals` | 17 | ❌ **not in types** |

Plus: `contracts`, `email_messages`, `documents`, `budget_lines`,
`calendar_connections`, `planner_invoices`, `playbook_tasks` and ~10
more all missing from types.

### Why this matters

When code references a column or table that's not in types, devs have
two options:

1. Update `types.gen.ts` manually (error-prone, drifts further from prod)
2. Use the `supabase as unknown as { from: ... }` cast (loses type safety)

Almost everyone picks (2). Result: 473 casts. Each one is a place where
a schema change breaks runtime silently without typecheck catching it.

The May 8 `planning_tasks.budget_line_id` 500 happened because the
API endpoint referenced a column that didn't exist in prod (migration
not applied) — but the code typechecked because the cast hid it.

T1.1 (migration auto-apply) fixes the "migration not applied" half.
T1.2 (this) fixes the "cast hides drift" half.

- Documentation of the Supabase CLI install + linking workflow below

**What this gets us:**

  migration to refresh `packages/db/src/types.gen.ts`
- Inventory of the 473 cast occurrences is visible in this doc for
  tracking down
- T1.1 + T1.2 Phase 1 together = the "migration auto-apply triggers
  type regen" workflow is established (Phase 2 wires it into CI)

### Required setup (one-time per developer machine)

```bash
# Install Supabase CLI (macOS via brew)
brew install supabase/tap/supabase

# Verify
supabase --version

# Login (opens browser to authenticate against your Supabase account)
supabase login

# Link this repo to the Acquired Planner project
cd ~/Documents/wedding-os
supabase link --project-ref dfyryyzizxcxtysduono

# Now run type regeneration
pnpm gen:types
```

### Future workflow

Whenever a new migration is committed:

```bash
# 1. Migration auto-applies to prod via Railway preDeploy (T1.1 part 2)
# 2. Locally, refresh types
pnpm gen:types

# 3. Review the diff in packages/db/src/types.gen.ts
git diff packages/db/src/types.gen.ts

# 4. Commit the regenerated types alongside the migration
git add packages/db/src/types.gen.ts
git commit -m "chore: regen types after <migration name>"
```

## Phase 2 — Eliminate the cast pattern (DEFERRED)

**Scope:** Reduce 473 casts → < 50, removing them everywhere the
regenerated types make them unnecessary.

**Estimated effort:** 1-2 full days of focused work.

**Why deferred:**

1. Requires Supabase CLI to be authed locally (one-time setup Hursh
   needs to do)
2. The 473-cast cleanup is mechanical refactoring that benefits more
   from being done in a single focused block than spread across the
   sprint
3. T1.3 (write-guard pattern) has higher immediate safety value — it
   eliminates the silent-failure class of bug entirely, regardless of
   whether casts are hiding column drift

**Phase 2 plan when picked up:**

1. Hursh runs the Supabase CLI install + link (5 min)
2. Run `pnpm gen:types` — produces a regenerated types.gen.ts that
   now includes vendors, leads, testimonials, proposals, contracts,
   email_messages, documents, budget_lines, etc.
3. Iterate over the top 10 cast-heavy files (each has 10-30 casts):
   - Delete the `as unknown as { from: ... }` wrapper
   - Use direct `supabase.from("table_name")` with full type safety
   - Compiler will surface any genuine column-name typos that the
     cast was hiding
4. Smoke tests (T1.4) catch any runtime regression from the cleanup
5. Commit per-file with clear messages
6. Repeat until cast count < 50

The 50 floor is intentional — some casts will remain for genuinely
dynamic queries, edge cases where Supabase types lack expressiveness
(like complex joins or RPC calls), or pre-migration tolerance
patterns. Those casts get a `// TODO: T1.2-cleanup-resistant` comment
documenting why they stay.
