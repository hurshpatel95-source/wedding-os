---

## The problem this solves

"`pnpm tsc --noEmit` passes" was the green light to ship features
across May 5-8. Typecheck doesn't catch:

- A new feature breaking the previously-working surface
- Silent failures where the API returns 200 but nothing happened
- Auth flow regressions
- Copy leaks (Hursh's wedding details appearing in user-facing pages)
- Cross-page navigation deadends

Tonight's 12 regressions surfaced when users complained, not when
the deploy happened. T1.4 makes them visible at CI time — failing
tests block the deploy from promoting.

## CI integration (deferred to follow-up)

Not yet wired. Options:

**Option A — GitHub Actions workflow** (recommended)
- `.github/workflows/smoke.yml` runs `pnpm smoke` on every push to main
- Failing tests fail the workflow
- Hursh sees red X in GitHub PRs / commits
- Bonus: can run on PRs to catch regressions before merge

**Option B — Railway post-deploy hook**
- After deploy succeeds, Railway runs `pnpm smoke` from a service
- If smoke fails, alert Hursh (Discord webhook, email)
- Doesn't roll back deploy automatically — would need Option A for that

**Recommended sequence:**
1. Option A first (cheap, visible feedback loop)
2. Option B later if we want production-side regression detection
3. Both don't BLOCK deploys (yet) — they signal regressions. Blocking
   requires more confidence in the suite (e.g. 0 flakes for 30 days).

## When tests fail

1. Read failure output — Playwright captures URL + selector
2. Re-run with `pnpm smoke:ui` to see the headed browser
3. Trace files land in `playwright-report/` — open with `pnpm exec playwright show-report`
4. If real regression: FIX, don't skip
5. If flaky: add a retry OR adjust timeout. **Do NOT `.skip()` without a tracking issue.**

## Why not Vitest / Jest / supertest

Considered:
- **Vitest + Testing Library** — component-level, not E2E. Misses the SSR + auth + RLS layer.
- **node:test + supertest** — HTTP-only, no browser, can't test auth flows that require cookies + redirects.
- **Cypress** — heavier, slower, more flakes than Playwright for our scope.

Playwright was the right choice because:
- Tests the deployed product (the actual artifact users use)
- Handles auth + cookies + redirects natively
- Headless chromium is fast enough (~40s for 11 tests)
- Trace + video capture is excellent for debugging prod failures
