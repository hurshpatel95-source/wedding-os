## The wedge

Everyone has image-generation APIs. Nobody has **wedding-domain prompt optimization with clarification questions in the loop.** The couple types vague intent → AI asks the 3-5 wedding-planner questions → optimized prompt goes to Higgsfield → image. The interactive clarification step is the difference between Midjourney (where you fight the prompt) and Acquired Planner (where the AI gathers context first).

**Locked principles:**

1. **Couples never write Midjourney-grade prompts.** The optimizer translates their casual input into a generation-ready prompt.
2. **The optimizer asks clarification questions before generating.** Multi-choice + free-text fallback. 3-5 questions max. Workspace-aware defaults pre-selected.
3. **Wedding-domain expertise lives in the per-tool question sets.** Dress asks silhouette/neckline/train. Venue mockup asks lighting/decor density. Cake asks tiers/style. The questions ARE the moat.
4. **Two-stage flow is the rule.** Stage 1: gather. Stage 2: generate. Never one-shot from vague input.
5. **Credits are the business model.** Each generation costs credits. B2B (planner-paid): planner's tier bundles N credits/month. B2C (couple-paid): one-time top-up or subscription.

## Architecture

### Stage 1: Clarification

```
POST /api/studio/<tool>/clarify
Body: { user_input: string, workspace_id: string }

Claude (wedding-aware, tool-specific system prompt):
  - Reads workspace context (venue, region, season, palette, guest count, etc.)
  - Returns:
    {
      questions: [
        {
          id: "vibe",
          label: "Vibe?",
          options: [
            { value: "lush_textural", label: "Lush + textural — peonies, ranunculus" },
            { value: "structured_classic", label: "Structured classic — roses, lilies" },
            ...
          ],
          allow_other: true,
          default: "lush_textural"  // smart default based on workspace
        },
        ...
      ],
      preview_prompt: "..." // the prompt as-of-now using defaults
    }
```

### Stage 2: Generation

```
POST /api/studio/<tool>/generate
Body: {
  user_input: string,
  answers: Record<questionId, string>,
  workspace_id: string,
  variant_count?: number  // default 4
}

Claude (wedding-aware prompt-finalizer):
  - Combines user_input + workspace context + answers
  - Returns optimized Higgsfield-ready prompt
  ↓
Higgsfield API:
  - generate_image with N variants
  - Returns image URLs
  ↓
Server:
  - Deduct credits
  - Store generation record (workspace_id, tool, user_input, answers, prompt, result_urls, cost)
  - Return result
```

### Shared modules

- `apps/web/lib/studio/prompt-optimizer.ts` — the wedge. Takes (tool, user_input, workspace_context, answers) → returns optimized prompt. Calls Claude. Per-tool prompt templates live here.
- `apps/web/lib/studio/higgsfield-client.ts` — thin HTTP wrapper around Higgsfield API. Feature-flagged: returns placeholder until `HIGGSFIELD_API_KEY` is in env.
- `apps/web/lib/studio/credits.ts` — credit ledger. Add, deduct, check balance. Backed by `credit_ledger` table (queued for T1.1 part 2).
- `apps/web/lib/studio/tools.ts` — tool registry: per-tool credit cost, system prompt, clarification question template.

## /studio hub UX

Route: `/studio`

Layout:
- Header: eyebrow "AI Studio · beta · couples burn credits, planners' tiers bundle them"
- h1: "Studio"
- Description: "Skip the Pinterest rabbit hole. Tell us what you want to see and we'll generate it tuned to your wedding."
- Credits balance pill (top-right): "12 credits · Top up" (B2C) OR "Astia Events tier — unlimited preview" (B2B)
- 2-3 column grid of tool cards. Each card:
  - Icon
  - Label
  - 1-line description
  - Credit cost chip
  - Last-used timestamp + thumbnail of last generation (if any)
- Footer: link to gallery (`/studio/history`) showing past generations across all tools, shareable

### Per-tool route: `/studio/<slug>`

Layout:
- Back link → `/studio`
- Tool header (label + cost chip)
- Input area (text/image/both per tool config)
- "Refine my prompt" button (triggers Stage 1 clarification API call)
- Inline expansion: clarification questions appear, multi-choice chips + free-text fields
- "Generate" button (triggers Stage 2 — deducts credits, calls optimizer + Higgsfield)
- Loading state: "Optimizing prompt... generating images..." (Higgsfield ~15s)
- Result: image grid with [Pick favorite] [Refine] [Regenerate all] actions
- Below: small "Show optimized prompt" expander (transparency for power users)

### Refine loop

Hitting "Refine" goes back to the clarification questions with previous answers pre-filled. User tweaks, re-generates. Deducts credits again. Each refinement is a new generation record.

## Credit system (queued for T1.1 part 2)

### Schema (one new table)

```sql
create table credit_ledger (
  id uuid primary key default uuid_generate_v4(),
  workspace_id uuid not null references workspaces(id) on delete cascade,
  delta integer not null,                  -- negative for spend, positive for top-up
  reason text not null,                    -- "topup_stripe" | "spend_tool_<slug>" | "grant_planner_tier" | "promo"
  metadata jsonb,                          -- tool slug, generation_id, Stripe charge id, etc.
  balance_after integer not null,          -- denormalized for fast reads
  created_at timestamptz not null default now()
);

create index credit_ledger_workspace_idx on credit_ledger(workspace_id, created_at desc);
```

### Helpers (in `apps/web/lib/studio/credits.ts`)

```ts
export async function getBalance(workspaceId): Promise<number>;
export async function spend(workspaceId, amount, reason, metadata): Promise<{ ok: boolean; balance: number }>;
export async function grant(workspaceId, amount, reason, metadata): Promise<{ balance: number }>;
```

### B2B tier integration (Move 3)

When Astia's monthly subscription renews via Stripe webhook, automatically grant her workspace + every active client workspace the tier's monthly credit allocation. The grant is a positive ledger row with reason="grant_planner_tier_renewal".

### B2C credit packs

Stripe Checkout for one-time credit purchases:
- 25 credits: $9
- 100 credits: $29
- 500 credits: $99 (best value)

Webhook → grant. Couples top up as needed.

### Defense

- Server-side balance check before every generation
- Atomic spend (no race between balance check + generation)
- Free preview tier: every workspace gets 5 free credits on signup
- Generation history per workspace (for "this didn't generate well, please refund" — manual planner review)

## Higgsfield integration

### What we need from Hursh

`HIGGSFIELD_API_KEY` in Railway env. Without it, the studio runs in **stub mode** — generates placeholder images (using DiceBear / unsplash / SVG cards) instead of real renders. UX is identical; the swap is one env var.

### Higgsfield endpoints we'll wrap

Based on the GEO project memory (which uses Higgsfield for avatar/video), the relevant endpoints:
- `generate_image` — text-to-image, supports prompt + negative_prompt + dimensions + variant_count
- `characters` — face-preserving generation (needed for dress-on-me, hair/makeup) — couple uploads engagement photos, Higgsfield trains a "character" once, subsequent generations preserve faces
- For venue mockup: img-to-img with structural preservation

### Model choices per tool

- Mood board: pure text-to-image, fast model
- Dress on me / Hair: character + outfit/style transfer
- Venue mockup: img-to-img with style guide
- Cake / Florals / Invitation: text-to-image with style refs

## Tone / voice for the clarification questions

This matters. Every question should feel like a friend who plans weddings asking, not a form. Examples:

❌ "Please select your floral arrangement style preference."
✅ "What's your floral vibe?"

❌ "Specify lighting condition for venue visualization."
✅ "When in the day are we seeing this — sunset, candlelit evening, midday?"

Short, conversational, multi-choice + free-text option always.
